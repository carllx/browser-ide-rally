# Operator UI 设计原则 (Operator UI Design Principles)

本文件定义 Rally 状态表面的核心设计原则与工程约束。面向 Agent 与开发者，保持原则级定位。

## 1. 核心定位 (Core Identity)

- **状态仪表盘与遥控器**：Rally Surface 是供人类操作者（Operator）快速掌握全局与触发关键操作的状态仪表盘与轻量遥控器，**不是长文阅读页面，也不是沉重的诊断控制台**。
- **深度阅读属于 Agent**：长篇对话阅读、差异分析与深层决策属于协作 Agent；Agent 应当通过 API、结构化状态快照、日志以及 Diagnostics 获取完整上下文。

## 2. 用户暴露必要性门禁 (User Exposure Necessity Gate)

核心原则：
> **任何内容进入用户界面之前，都必须证明：用户为了完成当前目标，确实需要看到、理解、决定或操作它。**

该门禁同时约束 **UI 呈现本身** 与 **用户交互**（涵盖文本、标签、状态、按钮、输入字段、确认弹窗、警告提示、错误说明以及技术信息）：

- **四问暴露测试 (The Four-Question Exposure Test)**：
  在向用户暴露任何界面元素之前，必须通过以下检验：
  1. **Need to see?** 用户当前是否确实需要看到它才能掌握关键全局或本地现状？
  2. **Need to decide?** 用户当前是否确实需要做出主观判断或偏好选择？
  3. **Need to act?** 用户当前是否确实需要执行操作才能推动当前流程？
  4. **Need to recover?** 用户当前是否处于异常恢复状态，确实需要这部分信息才能排除故障？
  若四者皆否，严禁向用户呈现。

- **审计分类词汇表 (Audit Vocabulary)**：
  在评审或设计任何界面元素时，统一使用以下四类词汇界定其归宿：
  - `REQUIRED`：用户完成当前核心目标必须直接可见或直接可操作的内容。
  - `ON-DEMAND`：次要技术证据与诊断详情，默认隐藏，仅在排查异常时通过渐进披露按需展开。
  - `MACHINE-ONLY`：纯机器、底层协议或内部状态机细节，永远不得直接暴露给人类操作者。
  - `REDESIGN`：因系统生命周期设计未闭环或机械机制外溢而强加给操作者的状态、警告、确认或勾选框（例如强制用户确认丢弃内部状态的 routine 守卫复选框）。**必须通过重构生命周期或底层机制予以消除，严禁用 UI 包装掩盖设计失败。**

- **目标与后果语言 (Human Goal & Consequence Language)**：
  界面呈现必须采用面向操作者目标与真实后果的自然语言，严禁向用户倾倒系统内部状态机代码或枚举术语（如 `NEW`、`UNKNOWN`、`BLOCKED`、`REBIND_UNHANDLED` 等）。

- **系统承担机械细节 (System-Owned Mechanics)**：
  凡机器可推导、可校验或可自动发现的事实（如会话对应的工作区路径、代码仓库、Hook 安装、版本号对齐等），完全属于系统与协作 Agent 的职责，严禁转嫁为用户的手工输入、反复核验或表单负担。

- **优先以可保留/可逆设计替代确认与警告 (Preserving Lifecycle over Confirmations)**：
  面对可能覆盖或替换旧事实的场景，优先采用“保留旧事实证据/可追溯”的生命周期设计，而不是靠弹出警告和勾选确认来免除系统维护历史事实的责任。

- **确认仅用于语义授权 (Semantic Authorization Only)**：
  确认交互仅保留给真正具有破坏性/不可逆的操作、显式重复发送、涉及隐私与安全权限边界、或真正需要人类主观偏好决策的场景。

- **不支持的控件优先隐藏 (Hide Unsupported Controls)**：
  项目不支持或当前上下文不可用的能力，优先直接隐藏；不支持的操作不自动获得灰显占位的展示资格，严禁让无意义的禁用按钮污染视觉焦点。

- **内部真相严格不变 (Strict Internal Invariants)**：
  简化操作者界面的同时，绝对不削弱系统内部的精确身份核验、版本锁 (revision locks)、唯一性排他与事实证据完整性。系统内部必须继续严格保持 Fail-Closed。

## 3. 首屏扫描效率 (Viewport & Scan Efficiency)

- **首屏项目聚合**：在标准桌面视口（First Desktop Viewport）内，N 个绑定的多项目应以 N 个紧凑的项目行/卡片形式直接呈现，实现一屏概览。
- **默认扫描语法 (Operator Scan Grammar)**：
  每个项目的紧凑语法为：`项目标识 (Project Identity) + Browser 标签 + IDE 标签 + Latest Result Indicator (红点 ●) + 诚实观察时间 + 仅当前可操作的关注点 (Actionable Attention)`。
- **消除例行状态噪音**：默认扫描视图中严禁渲染常规的 `NEW`、`NO_NEW_RESULT`、“新结果”、“无新结果”等大文本或例行徽章。

## 4. 红点指示器语义 (Latest Result Indicator)

- **非规范派生指示**：红点（●）是基于可靠完成事实推导出的**最新结果指示器 (Latest Result Indicator)**，用于提示哪一侧刚刚产生了新的可靠完成。
- **严禁作为真实源**：红点绝非 Baton、Turn Owner、Delivery Proof 或 Handled 真实源；红点的移动不代表前一端点已被标记处理，亦不改写底层的规范 Dual-NEW 状态。
- **侧级无盲目打点**：若出现仅能确定 IDE 侧最新但无法定位具体端点的情况（Side-level IDE Latest），指示器仅标注于 IDE 分组/侧级，严禁向任意具体 IDE 端点打红点。
- **不确定性显式呈现**：当顺序证据不可靠或存在观察缝隙时，呈现紧凑清晰的 `UNCERTAIN` 标记，严禁偏向任何一侧。

## 5. 渐进式披露与最小冗余 (Progressive Disclosure)

- **首屏仅保留核心意图**：原始 IDs（会话 ID、工作区路径、仓库地址）、版本号、具体游标、精确时间戳、Action 历史表格、Provider 凭证及历史故障一律移至 Details/Diagnostics 折叠区。
- **项目本地关注**：当前需要处理的 actionable 事项（如未解决的人工介入声明、端点未知状态）直接在对应项目行内以紧凑形式就地呈现，默认首屏不设立常驻大托盘霸占空间。
- **诚实的相对时间**：扫描视图使用诚实的相对观察时间（如“观察于 5 分钟前”），避免将观察时间误导为即时完成；精确 ISO 时间戳保存在属性或详情中。
